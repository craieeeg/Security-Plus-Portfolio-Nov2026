# 🛡️ Project 01: Secure a Small Business Network

### Business Scenario

A small business with 20 employees requires a secure network infrastructure that separates staff, management, and guest users.

The organisation needs to prevent unauthorised access while maintaining normal business connectivity.

### Objectives

- Design a secure network topology.
- Implement network segmentation.
- Configure access control lists.
- Secure network device administration.
- Test and validate network security controls.

### Tools

- Cisco Packet Tracer
- Network diagramming software
- Microsoft Word or Markdown

### Project Tasks

- [ ] Design the network topology.
- [ ] Configure appropriate IP addressing.
- [ ] Create VLANs for different departments.
- [ ] Configure inter-VLAN routing.
- [ ] Implement ACLs to restrict traffic.
- [ ] Configure SSH for secure administration.
- [ ] Test permitted and blocked connections.
- [ ] Document configurations and findings.

### Portfolio Evidence

- Network topology diagram
- Configuration screenshots
- Connectivity test results
- Security configuration explanation
- Completed network security report

**Skills demonstrated:** Network segmentation, access control, secure administration, network troubleshooting.

# 🔎 Project 02: Vulnerability Assessment

### Business Scenario

An organisation is preparing to deploy a new server and wants to identify security vulnerabilities before it becomes operational.

### Objectives

- Understand vulnerability scanning.
- Identify potential security weaknesses.
- Assess vulnerability severity.
- Recommend remediation activities.
- Validate security improvements.

### Tools

- VirtualBox
- Greenbone/OpenVAS or Nessus Essentials
- Windows or Linux virtual machine

### Project Tasks

- [ ] Create an isolated virtual lab.
- [ ] Deploy a test server.
- [ ] Install and configure a vulnerability scanner.
- [ ] Conduct an authorised vulnerability scan.
- [ ] Identify five security findings.
- [ ] Prioritise findings using severity and business impact.
- [ ] Recommend remediation measures.
- [ ] Apply suitable security fixes.
- [ ] Perform a follow-up scan.
- [ ] Produce a vulnerability assessment report.

### Portfolio Evidence

- Lab architecture diagram
- Initial vulnerability scan results
- Vulnerability severity table
- Remediation recommendations
- Before-and-after scan comparison
- Final assessment report

**Skills demonstrated:** Vulnerability management, risk prioritisation, remediation, security assessment.

# 🚨 Project 03: SOC Security Investigation

### Business Scenario

A company's security team has detected repeated failed login attempts against a workstation.

The security analyst must determine whether the activity represents a potential security incident.

### Objectives

- Understand security monitoring.
- Investigate suspicious authentication activity.
- Analyse security event logs.
- Identify indicators of compromise.
- Document incident findings.

### Tools

- Wazuh or Splunk
- Windows Event Viewer
- Windows or Linux virtual machine

### Project Tasks

- [ ] Deploy a security monitoring environment.
- [ ] Configure event log collection.
- [ ] Generate failed login attempts within the lab.
- [ ] Identify relevant authentication events.
- [ ] Analyse event timestamps and source information.
- [ ] Create a detection rule or alert.
- [ ] Investigate the suspicious activity.
- [ ] Recommend appropriate response actions.
- [ ] Produce an incident investigation report.

### Portfolio Evidence

- SIEM dashboard screenshots
- Security event logs
- Detection rule configuration
- Incident timeline
- Investigation findings
- Incident response recommendations

**Skills demonstrated:** Security monitoring, log analysis, threat detection, incident investigation.

# 📝 Project Documentation Standards

Each completed project will include:

1. **Project Overview:** Description of the business scenario.
2. **Objectives:** What the project aims to achieve.
3. **Tools Used:** Software and technologies implemented.
4. **Implementation:** Steps taken to complete the project.
5. **Testing:** Evidence demonstrating whether the solution worked.
6. **Findings:** Security weaknesses identified and improvements made.
7. **Reflection:** Lessons learned and future improvements.

Screenshots, configurations, and reports will be included where appropriate.

---

# 🔒 Ethical and Security Considerations

All technical activities will be conducted within authorised, isolated laboratory environments.

- No unauthorised vulnerability scanning.
- No testing against third-party systems without permission.
- No collection of real employee credentials.
- No publication of passwords, API keys, or sensitive information.
- Any attack simulations will use controlled lab environments.
